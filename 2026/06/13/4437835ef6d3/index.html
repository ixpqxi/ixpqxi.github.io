Log4j2漏洞

Log4j2

1 背景知识

Log4j2 是 Apache Logging Services 下的 Java 日志框架，常见于 Spring、Dubbo、ElasticSearch、Kafka 以及大量企业级 Java 应用中。日志框架本身通常不直接处理业务逻辑，但它位于请求处理链路的通用位置，用户输入、HTTP 头、异常信息、用户名、搜索关键字等内容都可能被写入日志，因此一旦日志格式化阶段存在危险解析能力，攻击面会非常广。

这次漏洞通常被称为 Log4Shell，核心编号是 CVE-2021-44228。它的本质不是“打印日志会执行命令”，而是 Log4j2 在格式化日志消息时支持 ${} 形式的 Lookup 语法，其中 jndi Lookup 可以把字符串继续交给 JNDI 处理。当攻击者可控的字符串进入日志消息，并被 Log4j2 当作 Lookup 表达式解析时，就可能触发对外部 JNDI 资源的访问，进一步导致远程类加载、信息泄露或其他后续利用。

从攻击链路上看，可以拆成三层：

  • 应用层：攻击者把特殊字符串放入会被记录日志的位置，例如请求参数、请求头、用户名、异常消息等。
  • 日志层：Log4j2 的 PatternLayout/MessagePatternConverter 在格式化消息时识别 ${}，并通过 StrSubstitutor 和 Interpolator 找到对应的 Lookup。
  • JNDI 层：JndiLookup 将后续内容交给 InitialContext.lookup()，由 JNDI 根据协议和名称继续解析资源。
