JNDI注入基础

JNDI基础

1 概念

JNDI全称为 Java Naming and DirectoryInterface（Java命名和目录接口），是一组应用程序接口，为开发人员查找和访问各种资源提供了统一的通用接口，可以用来定义用户、网络、机器、对象和服务等各种资源。JNDI支持的服务主要有：DNS、LDAP、CORBA、RMI等。简单点说，JNDI就是一组API接口。每一个对象都有一组唯一的键值绑定，将名字和对象绑定，可以通过名字检索指定的对象，而该对象可能存储在RMI、LDAP、CORBA等等。

服务名 描述
Java Naming 命名服务是一种键值对的绑定，使应用程序可以通过键检索值
Java Directory 目录服务是命名服务的自然扩展。这两者之间的区别在于目录服务中对象可以有属性，而命名服务中对象没有属性。因此，在目录服务中可以根据属性搜索对象
ObjectFactory 用于将Naming Service（如RMI/LDAP）中存储的数据转换为Java中可表达的数据，如Java中的对象或Java中的基本数据类型。每一个Service Provider可能配有多个Object Factory

1.1 相关知识

ReferenceWrapper_Stub的核心职能是作为远程对象的代理，当客户端调用一个远程对象的方法时，实际上调用的时ReferenceWrapper_Stub，一个静态生成的客户端存根Stub，负责将方法调用参数序列化，并通过网络发送给服务端，接收服务端的结果，再将其反序列化返回给客户端。

在RegistryContext的decodeObject中先判断是否为ReferenceWrappe，也就是判断是否为Reference对象。其中的getObjectInstance()就是获取一个对象的初始化方法

javax.naming.Reference类是一个核心的JNDI对象，当一个对象无法直接存储在命名服务（JNDI、LDAP）中或无法指导客户端如何重新创建该对象时，Reference就会发挥作用。其存储着如何创建对象的元数据，包括：

  • ClassName：该对象在远程的实际Java类名
  • FactoryClassName：负责创建该对象的工厂类名
  • FactoryClassLocation：一个url列表，指明从哪里下载该工厂类的字节码
  • RefAddr：一组地址信息，包含对象创建所需要的参数
